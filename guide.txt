Churn Prediction Dashboard
Step-by-Step Build Guide using Google Antigravity
1. Objective
Build an end-to-end machine learning system that predicts which customers are likely to churn (cancel or stop using a service), and present those predictions through an interactive dashboard that a non-technical stakeholder could use to make retention decisions.
This is not just a notebook exercise. The goal is to demonstrate the full pipeline: data → cleaning → modeling → evaluation → interpretation → a usable interface. That end-to-end thinking is what differentiates this project.
2. Recommended Stack
You will be building this using Google Antigravity, an agentic IDE where you describe tasks in natural language and an AI agent plans, writes, and verifies the code across your editor, terminal, and browser. Below is the stack the agent will set up for you.

3. Dataset
Use the Telco Customer Churn dataset (~7,043 rows, 21 columns) — the standard dataset for this kind of project.
https://www.kaggle.com/datasets/blastchar/telco-customer-churn
Target column: Churn (Yes/No)
Key features: tenure, MonthlyCharges, TotalCharges, Contract, InternetService, PaymentMethod
Known quirk: TotalCharges sometimes loads as text with blank values — must be cleaned
Class balance: roughly 27% churn — mildly imbalanced, so accuracy alone is not a reliable metric
4. Step-by-Step Build Process
Work through these steps inside Google Antigravity. For each step, open a new Agent task, describe the goal in plain language (a sample prompt is given), let the agent produce a plan and code, review the diff, and approve or ask for changes before moving on.
Step 1 — Set up the project
Create a new folder/workspace in Antigravity, e.g. churn-prediction-dashboard.
Open the Agent Manager and start a new task.
Ask the agent to scaffold the project: a Python virtual environment, a requirements.txt, and a folder structure (data/, notebooks/, src/, app/).
Sample prompt to the Antigravity agent:
"Set up a Python project called churn-prediction-dashboard. Create a virtual
environment, a requirements.txt with pandas, numpy, scikit-learn, xgboost,
matplotlib, seaborn, streamlit, and joblib. Create folders: data/, notebooks/,
src/, app/. Initialize a git repository."
Step 2 — Get and load the dataset
Download the Telco Customer Churn CSV from Kaggle and place it in the data/ folder (or ask the agent to fetch it via the Kaggle API if you provide credentials).
Ask the agent to write a script that loads the CSV with pandas and prints basic info (shape, dtypes, missing values).
Step 3 — Explore and clean the data (EDA)
Ask the agent to check for missing values and fix the TotalCharges column (convert to numeric, handle blanks).
Generate summary statistics and a few plots: churn rate by contract type, churn rate by tenure, churn rate by internet service.
Review the plots the agent produces — they will guide your feature choices later.
Step 4 — Feature engineering
Ask the agent to encode categorical variables (one-hot encoding for most, label encoding where ordinal).
Scale numeric features (tenure, MonthlyCharges, TotalCharges) if using Logistic Regression.
Optionally create derived features, e.g. average charge per month of tenure, or a tenure bucket (0-12, 13-24, 25+ months).
Split the data into train and test sets (e.g. 80/20), stratified on the target column.
Step 5 — Train the models
Ask the agent to train a Logistic Regression model as a baseline.
Then train an XGBoost classifier for comparison.
Evaluate both using precision, recall, F1-score, and ROC-AUC — not just accuracy, since the dataset is imbalanced.
Ask the agent to plot a confusion matrix and ROC curve for the better-performing model.
Sample prompt:
"Train a Logistic Regression and an XGBoost classifier on the cleaned churn
dataset. Evaluate both with precision, recall, F1, and ROC-AUC. Show a confusion
matrix and ROC curve for the best model. Save the best model with joblib."
Step 6 — Interpret the model
Ask the agent to extract feature importance (XGBoost) or coefficients (Logistic Regression).
Identify the top 5-10 factors driving churn (commonly: contract type, tenure, internet service type, monthly charges).
Write a short summary in plain language — this becomes the 'insights' section of your dashboard.
Step 7 — Save the trained model
Ask the agent to save the final model (and any encoders/scalers) using joblib so the dashboard can load it without retraining.
Step 8 — Build the Streamlit dashboard
Ask the agent to build a Streamlit app (app/app.py) that: loads the saved model, lets a user input or upload customer data, shows the churn prediction and probability, and displays the top churn drivers as a chart.
Add filters so a user can browse customers by risk level (high/medium/low churn risk).
Run the app locally with streamlit run app/app.py and review it in the browser — Antigravity's browser-use agent can even test it for you.
Sample prompt:
"Build a Streamlit dashboard in app/app.py that loads the saved churn model,
accepts a customer’s details as input (or a CSV upload for batch scoring), shows
the predicted churn probability, flags high-risk customers, and displays a bar
chart of the top features driving churn."
Step 9 — Test and refine
Manually test edge cases (e.g. a customer with 0 tenure, very high charges).
Ask the agent to add input validation and clean error handling.
Polish the UI: titles, layout, colors, short descriptions of each field.
Step 10 — Deploy and package
Push the project to GitHub with a clear README (problem, approach, stack, results, screenshots).
Deploy the Streamlit app for free on Streamlit Community Cloud, or record a short demo video/GIF.
Add the live link and GitHub repo to your portfolio or resume.
5. Working Effectively with Google Antigravity
Break the project into the small tasks above rather than one giant prompt — smaller tasks are easier for the agent to plan, execute, and for you to verify.
Review each Artifact (code diff, plan, or task summary) before approving — treat the agent like a fast junior developer whose work you're reviewing.
Use comments on Artifacts to redirect the agent instead of rewriting prompts from scratch.
Let the agent use the terminal to run tests, install packages, and execute scripts rather than doing this manually.
Ask the agent to verify: e.g. "run the script and show me the output" or "open the Streamlit app in the browser and confirm it loads."
6. Outcome
By the end, you will have: a cleaned dataset, two trained and compared models, a clear explanation of what drives churn, and a working interactive dashboard — deployed and shareable. This demonstrates end-to-end thinking, not just notebook code.
